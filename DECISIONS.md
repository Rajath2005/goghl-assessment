# Decisions

**Durability.** The supplied MongoDB is standalone. Each business change is one journaled document with a unique workspace sequence. The queued reply is also its outbox job. A competing append retries against the new stream head and rechecks its preconditions. Unique keys cover event IDs, provider message IDs, client references and the first holder of a conversation. Snapshot, inbox and WebSocket replay read the same history. Inbound ordering uses provider time, then message ID for ties.

**Delivery.** Workers acquire a ten-second lease and use a shared Redis bucket of eight requests with four tokens restored per second. A single outstanding HTTP attempt per workspace lets a 429 establish the cooldown before another sender runs. MongoDB retains the next attempt and fences updates by lease token. Every retry reuses the original workspace/client-reference idempotency key. Either terminal callback wins over a later sent event. A duplicate reply reference retains its first accepted payload. Temporary failures back off indefinitely.

**Product.** Claims are advisory ownership. Authorized agents can collaborate on a thread. Closure is explicit, and an agent can reopen it. Login uses PKCE, a browser-bound single-use state, nonce and JWKS signature verification. Each HTTP operation and socket checks session membership. The browser encrypts private notes with an out-of-band workspace key. Elasticsearch search and bonus billing were omitted to prioritize delivery, isolation and the working inbox.

**Limits.** A busy tenant contends on one append sequence. Conversation lists aggregate history, long threads load in full, and connected sockets poll indexed event history every 250 ms. These choices fit the assessment workload. Production scale would require bounded thread reads, materialized projections and efficient wakeups. Delivery depends on Pigeon's idempotency retention. If its final callback exhausts all six delivery attempts during downtime, its public API exposes no lookup to repair the last known status. The first crash check on a Windows bind mount missed eight inbound messages. A clean Linux-native rerun recovered all 171 and scored 14/14.
